Faster Home and Work returns

The shell was cached; the overview data was not.

HTML, scripts, styles and icons already use the offline shell cache. Home and Work were still rebuilding from fresh requests on every visit. They now reuse validated, memory-only snapshots for up to one minute while fresh reads run in the background.

Cached cards are previews.

The cache is scoped to the server, sign-in, session and effective permissions. Writes and sign-out clear it; a denied endpoint loses its own snapshot too. A late response cannot refill it after a write or account change. Workflow details and actions still perform fresh reads and authorization checks.

On a cold visit, the compact checking state remains. On a warm visit, last checked records appear immediately with the current checking state, then reconcile with the server. Nothing personal is written to persistent browser storage. Clock, action forms and evidence are not given snapshot-based action authority.

Review brief and method
  1. Professional check: separate asset caching, data latency and rendering; measure cold/warm tab returns and trace invalidation, isolation and stale-action behavior.
  2. Raw material: service-worker fetch rules, API remembered-GET support, live Home/Work readers, effective-permission identity, mutation/sign-in lifecycle and actual disposable workflow responses.
  3. Methods/tools: extend the existing bounded API memory cache rather than cache API traffic in the service worker. Use Playwright timings under a fixed 2.5-second simulated delay, fresh-response comparisons and stale-link checks; unit tests for permission scope, expiry, writes, late replies and account/server changes. Taste’s app-screen loading guidance explicitly keeps known values during refresh. UI UX Pro Max’s loading search returned lazy-image guidance rather than a cache-specific match; its general feedback rules support an honest checking state. No new motion or dependency is added. Sites delivers this same private preview.
  4. Independent evidence: warm records must appear before delayed network completion; fresh completion removes old cards, and a stale card’s detail cannot offer an action. Snapshot tests reject another scope, expired data and late post-write responses; sign-out and 403 drop remembered data. The prior generated app fails the warm-return timing check.

Brief: Diagnose why mobile tab returns feel uncached. Make existing Home/Work overviews display their last validated data promptly while fresh reads continue. Reuse the existing memory cache with bounded lifetime, strict identity/grant scoping and write/access invalidation. Preserve live workflow checks, error/unknown states, compact cold loading and existing navigation. Measure cold/warm behavior and stale/late/unauthorized cases, then publish this actual-code interactive preview without committing app changes.

Verification and remaining limits

Playwright results will be written here after verification.

Browser interactions and animations run real app code. The managed test browser blocks file:// navigation, so verification serves this same standalone HTML on loopback. Opening the file directly in other browsers is not yet verified. Records were captured from a disposable backend at build time; this file replays them offline. Business writes, uploads and uncaptured destinations are explicitly blocked. Only notification read markers and shortcut preferences may update isolated sample memory. Test records, history and forms never reach the live app.

Notification read markers, saved shortcut choices and browser storage use memory only. This does not test persistence across restart, camera/GPS, printers, a physical phone, a real screen-reader session, or first-time employee understanding. Shared code applies across mobile, but the browser checks cover the named representative screens and controls rather than every legacy screen. An exploratory full-page 200% CSS zoom inside an already 320-pixel phone frame reduced its effective layout to about 160 pixels and exposed overlap in the existing global header/dock. That app-wide shell limitation remains outside this Sales-list refinement; the tested 320/390-pixel layouts below use normal page zoom.
