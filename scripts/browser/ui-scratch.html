Verification and remaining limits

Playwright results will be written here after verification.

Browser interactions and animations run real app code. The managed test browser blocks file:// navigation, so verification serves this same standalone HTML on loopback. Opening the file directly in other browsers is not yet verified. Records were captured from a disposable backend at build time; this file replays them offline. Business writes, uploads and uncaptured destinations are explicitly blocked. Only notification read markers and shortcut preferences may update isolated sample memory. Test records, history and forms never reach the live app.

Notification read markers, saved shortcut choices and browser storage use memory only. This does not test persistence across restart, camera/GPS, printers, a physical phone, a real screen-reader session, or first-time employee understanding. Shared code applies across mobile, but the browser checks cover the named representative screens and controls rather than every legacy screen. An exploratory full-page 200% CSS zoom inside an already 320-pixel phone frame reduced its effective layout to about 160 pixels and exposed overlap in the existing global header/dock. That app-wide shell limitation remains outside this Sales-list refinement; the tested 320/390-pixel layouts below use normal page zoom.
