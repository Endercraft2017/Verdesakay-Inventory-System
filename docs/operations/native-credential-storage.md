# Native credential storage and queue migration

The installable Capacitor Android client now uses pinned
`@aparajita/capacitor-secure-storage@8.0.1`. Its Android implementation encrypts data with
AES-GCM and an Android Keystore key. The application refuses the plugin's web fallback and
keeps bearer access in memory while running. The ordinary browser/PWA continues to use its
HttpOnly session cookie. This change does not claim protection from a compromised running
app, rooted device or a complete forensic examination.

## Implemented boundaries

- `mobile-app/native-credentials.mjs` serializes OS-vault access. New sessions store an opaque
  token and its exact HTTPS company origin in the vault. No bearer is written to localStorage,
  sessionStorage or the native queue metadata. Shared-device sessions are memory-only.
- Startup waits for vault initialization and removes old plaintext web-storage and IndexedDB
  token mirrors. **Unbound old tokens are not automatically adopted. Users sign in again.**
  Their old records do not prove which server issued them; guessing would risk sending one
  company's credential to another company. No live server sessions were revoked by this audit.
- A missing/locked/broken vault blocks sign-in persistence; it never falls back to plaintext.
  Failed persistence attempts a bounded, best-effort revocation at the original issuing server.
  An offline server may prevent that revocation; normal server expiry/revocation still applies.
- Logout clears memory immediately, writes a non-secret signed-out marker, and removes the
  vault record before reloading. The marker prevents failed deletion from restoring a session
  on restart. A pending login/write cannot publish after logout. Storage failure leaves the
  sign-in screen with an error instead of silently reopening the account.
- Only a session returned by a login at the current server can be accepted by the API client.
  An in-flight login result cannot be rebound to a different company or reopen a signed-out
  session. HTTP and URLs containing userinfo are refused before transmitting credentials.
- Company origin and actor ID bind every new queued operation. Foreground and worker replay
  check both. A queued request also checks its original server immediately before sending.
  Browser background replay uses cookie CSRF headers and `X-Queue-Actor`, preventing a changed
  browser account from sending a previous account's work. Native background worker replay is
  disabled; the foreground obtains its credential from memory.
- Older queue records missing actor/server binding remain stored and cannot replay automatically.
  The Pending sync page explains that separate/older work needs review and does not claim it
  is all synced. Storage errors show unknown status with Retry. No business rows are deleted
  by the credential migration.
- Personal mobile-cache ownership now includes the company origin. Existing same-origin browser
  cache ownership migrates safely. On the first upgraded native sign-in, older personal caches
  and localStorage drafts with unbound ownership are cleared to prevent cross-company display;
  **review/save open drafts before installing the update**. IndexedDB queued business operations
  are retained separately. Native company-address settings survive personal-cache cleanup.
- Android disables backup and explicitly excludes all app-data domains from cloud backup and
  device transfer. The bridge also requests non-synced, device-only keychain storage for a future
  iOS build, but there is no built/tested iOS application in this repository.

The vault does not encrypt every photo, HR cache or business draft on the phone. Those data
remain separate privacy/minimization and device-protection work. It does not make tokens
short-lived, add refresh rotation, pin TLS certificates, or replace server-side authorization.

## Build and local evidence

In `mobile-app/`, run `npm ci`, then `npm run sync`. The build bundles the plugin and native
credential bridge into the APK web assets and includes third-party license notices. Android
plugin settings/Gradle wiring are generated by Capacitor sync, not handwritten. Both native
and web clients still share `public/js/api.js`; PWA cache v110 refreshes the changed shell.

Local checks cover the actual API client and credential state machine: missing plugin, failed
writes/deletion, logout/login races, restart, shared sessions, HTTPS and cross-server rejection,
plaintext removal and retention of queued work. Queue tests exercise real fake-indexeddb
transactions and execute the actual service-worker replay function, including cookie/actor
headers and legacy/foreign-record rejection. Browser tests exercise web/PWA login, authenticator
and recovery flows. The OS vault itself is a test provider in these JavaScript checks, not an
emulated Android Keystore.

The native bundle and `cap sync android` completed. Java 21 is present, but this workspace has
no configured Android SDK/build tools. **No APK compilation, Keystore/device extraction test,
backup/transfer experiment or physical Android acceptance is claimed.** Do not distribute a
new installer until these checks pass in an Android build/device environment.

## Final rollout checks — after engineering

1. Prepare a signed staging APK from a clean mobile lockfile install with the Android SDK.
   Verify that the SecureStorage plugin is present in the installed binary.
2. Review/save unfinished localStorage drafts and reconcile older queued work before upgrading.
   Keep unknown operations for investigation; do not edit their actor/server or create another
   retry key merely to force replay. Determine the original company/actor and authoritative
   business state before any controlled correction.
3. Test fresh sign-in, MFA, process restart, logout, shared-device sign-in, locked storage,
   airplane mode/reconnect and original-key queue recovery on a physical Android device.
4. Inspect the app sandbox after login/logout/upgrade: no raw bearer in web storage or queue
   metadata; persisted vault data is ciphertext. Exercise supported backup/device-transfer
   tooling. Confirm it does not migrate usable sessions or private caches.
5. Confirm TLS behavior at the actual cloud and office host. Existing user-installed site CAs
   remain a deliberate trust choice; certificate pinning/rotation acceptance is still unverified.

No phone access, account setup, credentials or hosting changes are requested from the owner
while local engineering checks are running. Never send bearer tokens or passwords in chat.
